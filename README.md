# Solder808

808 系ドラムの 11 チャンネル・16 音色（BD / SD / LT・LC / MT・MC / HT・HC / RS・CL / CP・MA / CB / CY / OH / CH）の回路をブラウザ内で 1 サンプルずつ解いて鳴らす試作。部品の許容誤差・経年劣化・温度を「個体」として変えられる。

https://tainakanchu.github.io/Solder808/

最初の画面のジャンル別プリセットを押すとすぐ鳴る。プリセットは 2 小節で、2 小節目の最後 4 マスがおかず（1 小節にも切り替えられる）。アレンジ（定番を崩さない範囲の変化）、個体ガチャ（製造年・状態・置き場所で名前のついた個体を引く）、共有リンク（パターン・テンポ・個体・ノブ・切り替えスイッチを URL に入れる）がある。

- 実機と同じく、タム／コンガ（3 チャンネルそれぞれ）、リムショット／クラベス、クラップ／マラカスはスイッチで切り替える。行の名前の横の 2 つ並んだボタンを 1 回押すと切り替わり、設定はパターンごとに保存される。
- タム・リム・シンバルの 5 行は折りたためる（使っているパターンでは自動で開く）。たたんでいても、どのマスで鳴るかは見出しの行に点で出る。
- スマホ幅では 1 小節 16 マスを 8 マスずつ 2 段に折り返す。
- キーボードで鳴らせる: A S D F G H（BD SD CH OH CP CB）、J K L ; '（LT MT HT RS CY）。
- 詳細設定の「音質」: 自動（おすすめ）／高品質（内部 2 倍オーバーサンプル）／軽量（1 倍）。自動では再生中に負荷 80 % 超えが約 2 秒続くと軽量に切り替えて知らせる（そのページを開いている間は自動では戻さない）。軽量では計算がほぼ半分になり、音は少し変わる。

## MIDI クロック同期

再生ボタンの並びの「同期」で MIDI 入力を選ぶと、その入力の MIDI クロック（24 PPQN）・スタート／ストップ／コンティニュー・ソングポジションに合わせて鳴る。Web MIDI が使えるブラウザ（Chrome / Edge 系）だけで出る。

- Mac で同じマシンの DAW と合わせるときは、Audio MIDI 設定で IAC ドライバを有効にし、DAW から IAC バスへクロックを送る。
- 音はクロックを受けた時刻から「遅延」の表示ぶん遅れて鳴る（出力遅延＋ジッタ吸収の 20 ms）。DAW 側の MIDI クロックの同期ディレイ（Ableton Live なら Preferences の Link/Tempo/MIDI にある MIDI Clock Sync Delay）をその値だけマイナスにすると揃う。
- スイングと連打は、クロックの間隔から測ったテンポで計算する。
- 相手が再生中に途中から繋いでも、クロックを受けた時点から追従する（ソングポジションが来ていればその位置、無ければ受けた位置を拍頭とする）。相手のストップ後や自分で止めた後は、スタート／コンティニューを受けるまで鳴らない。
- Windows では MIDI ポートを基本的に 1 アプリしか同時に開けない。DAW やメーカー製ユーティリティが開いていると Chrome から見えない、または開けない。
- Windows で MIDI 機器やオーディオインターフェースを後から繋いだときは、Chrome を常駐も含めて完全に終了して起動し直さないと入力が出ないことがある。
- オーディオインターフェースの MIDI は、メーカーのドライバが入っている前提である。

## 使い方

```bash
nix develop --profile .nix-profile/dev   # GC で devShell が消えないようにする
cd web && pnpm install && pnpm dev
```

- `pnpm dev` / `pnpm build` は先に Rust を wasm32 向けにビルドして `web/src/assets/solder808.wasm` に置く（`wasm-opt` が要る。devShell に入っている）。
- `pnpm lint`（oxlint）、`pnpm fmt`（oxfmt）、`pnpm typecheck`。
- `cd dsp && cargo test --release`。`engine::fuzz` はつまみ・部品・個体をランダムに変えて、出力が有限で無音時に Newton が上限に張り付かないことを確かめる。`cargo test --release long_play -- --ignored --nocapture` で PPAP を 10 分鳴らして変化を見る。
- SNS 用の OG 画像は `web/og-image.svg` が元。直したら `cd web && nix run nixpkgs#resvg -- og-image.svg public/og.png` で PNG を作り直す。
- `main` に push すると GitHub Actions が同じ devShell でビルドして GitHub Pages に公開する（`.github/workflows/pages.yml`）。
- ネイティブで WAV を書き出して測る: `cd dsp && cargo run --release --bin render -- ../renders`

## 構成

- `dsp/` Rust。`circuit.rs` が MNA ソルバ（コンデンサは台形則、ダイオードと飽和オペアンプは毎サンプル Newton 法）。`bd.rs` / `sd.rs` / `hh.rs` / `cp.rs`（クラップ・マラカス） / `cb.rs` / `tom.rs`（タム・コンガ） / `rs.rs`（リムショット・クラベス） / `cy.rs` が各ボイスの回路、`blocks.rs` が共通の回路ブロック、`parts.rs` が個体差と経年変化。
- `web/` Vite + Preact + TypeScript（`preact/hooks` を直接使い、JSX は tsconfig の `jsxImportSource` で Preact に向ける）。`src/music/` にプリセット・アレンジ・個体ガチャ・共有 URL。`src/audio/processor.ts` が AudioWorklet で、wasm-bindgen なしの C ABI を直接呼ぶ。シーケンサもワークレット内でサンプル単位に動く。

## 回路モデルの範囲

- 回路として解いている: BD の bridged-T 共振・再生帰還（decay）・ダイオードによるピッチ降下・tone・出力カップリング、SD の 2 つの共振とノイズのフィルタとエンベロープ、HH のバンドパス・エンベロープ・チョーク・出力ハイパス、クラップのバンドパスと 2 つのエンベロープ、カウベルのバンドパスと速い・遅いエンベロープ、タム・コンガの bridged-T 共振（待機バイアスのかかったダイオードでピッチが打撃直後から下がる。タムだけノイズのバーストが混ざる）、リムショットの 2 つの共振とハイパス、クラベスの共振、マラカスのノイズのハイパスとエンベロープ、シンバルの 2 つのバンドパスと 3 つのエンベロープ経路（tone で低域と高域の比、decay で長い経路の減衰）。
- 式で近似している: HH とシンバルが共有する 6 個とカウベルの 2 個の矩形波発振器（周波数は R と C の部品値から計算）、ノイズ源、VCA の利得カーブ。
- 共通回路（部品表の「共通」タブ）: 15 V 電源（出力抵抗＋平滑コンデンサ）は各音色の消費電流で下がり、全オペアンプの振れ幅とトリガー電圧に効く。アクセント線は 1 本の出力抵抗を、同時に鳴った音色の入力抵抗で分け合うので、多く重なるほどアクセントが弱まる（BD 単独 0.749 → 11 チャンネル同時 0.580）。ミキサーはレベル用ボリューム（分圧）→ 47 kΩ → 反転加算オペアンプ → 出力コンデンサ。分圧器は等価なノートン電源に置き換えて解いている。
- 電源の電圧降下は全チャンネル同時でも約 4 %（14.4 V）と小さい。部品表で R1 supply output を大きくすると効きが分かりやすい。
- 部品定数は 808 の信号の流れに合わせた代表値で、サービスマニュアルの回路図とは突き合わせていない。
- 連立方程式は回路の形から決まる疎な消去手順を使い回して解く（ピボットが怪しいときだけ密な部分ピボットに戻って手順を作り直す）。行列の線形部分は部品値が変わったときだけ分解し直し、ダイオードとオペアンプは Newton の 1 反復ごとに低ランク更新（Woodbury）で解く。
- 負荷の目安（48 kHz・高品質、2.1 GHz の Xeon で計測）: 全 11 チャンネルを毎ステップ鳴らす極端な負荷でネイティブ実時間の約 1.7 倍、wasm でブロック予算の約 50 %。プリセットは wasm で重いもの（ディスコ・エレクトロ）でも平均 30 % 弱。軽量にするとほぼ半分になる。
- 鳴り終わった音色は、出力が −90 dBFS を下回って 50 ms たつと計算を止める。止めたあとも回路の状態は粗い時間刻みで静止点まで減衰させ続けるので、次の一打は止めずに計算した場合と変わらない。
- AudioContext は 48 kHz で開く（96 kHz のオーディオインターフェースでも内部の計算量が倍にならないように）。
- 画面の「負荷」は計算時間の割合。ワークレットに高精度タイマーがあればブロック 1 つの最大値（瞬間）も出す（Date.now しかない環境では 1 ms 刻みで不正確なので出さない）。途切れるときは詳細設定の「出力バッファ」を大きくできる。
- decay を最大にすると、部品のずれ方や経年・温度によっては BD が自己発振したり長く鳴り続けたりする個体がある。
